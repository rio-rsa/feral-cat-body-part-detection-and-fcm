# Feral Cat Object Detection & FCM

This project combines **object detection (YOLOv12)** with a **Feature Concatenation Model (FCM)** to identify individual feral cats. It is the code for the paper *Automatic Body-part-based Individual Feral Cat Identification from Camera Trap Images* (Akbar, Rees, Fleming & Sohel, *Ecological Solutions and Evidence*).

Each step below says which notebook to run. The notebooks are in [`notebooks/`](notebooks) and are numbered in the order you run them.

## Data

The camera trap images are **not included** in this repository. They come from a feral cat study in the Glenelg and Otway regions of Victoria, Australia ([Rees et al., 2023](https://doi.org/10.1111/1365-2664.14402)). For access, please contact Matthew Rees.

## Step 3: Comparing Object Detection vs Manual Labels (FCM)

Now that we have evaluated the performance of YOLOv12 on our dataset, the next step is to compare object detection with manual labelling in the Feature Concatenation Model (FCM). To do this fairly, we require two separate datasets:

1. One containing manually labelled body parts (based on human annotations), and

2. Another containing automatically labelled body parts (generated by the trained YOLOv12 model).

Both come from the same set of test images, which are:

- Manually cropped using their original annotations to serve as the ground truth, and

- Automatically labelled by a YOLOv12 model for detection-based evaluation.

However, since some of these test images may have been part of the training or validation set in the initial YOLOv12 experiment where we evaluated its performance (where we used a 70/15/15 split), we must re-train the model so that none of these test images are a part of the training data, to avoid data leakage.

We also need a much bigger test set than 15%. The FCM needs the same number of images of every body part for each cat (see Step 8), so many crops get thrown away, and YOLOv12 also finds fewer body parts than we label by hand. With a 15% test set, some cats were left with only one or two images of a body part, or none at all. To make sure there's enough data left for the FCM, we introduce a new data split of **25% train / 15% val / 60% test** and retrain the YOLO model from scratch. To make up for the smaller training set, it is trained for 20 epochs instead of 10.

## Step 8: FCM Tests

We will train a FCM on the following:
1. **Test 1:** automatically annotated data
2. **Test 2:** sanitised automatically annotated data (checked and corrected by hand)
3. **Test 3a:** manually annotated data
4. **Test 3b:** manually annotated data, cut down to the same size as Test 2
5. **Test 4:** manual and sanitised automatic data combined

All the datasets are made with `04_prepare_fcm_datasets` and saved to `outputs/fcm_datasets`. Steps marked ✋ are done by hand.

**Balancing:** the FCM concatenates the four body parts of a cat before classifying, so every body part of a cat needs the same number of images. For each cat, we randomly remove images until every body part has the same number as its rarest body part.

### Test 1

We first must obtain a consistent test set to use, as all of these will be tested on the same set. We balance the automatic crops from Step 6 and then split them into roughly a 70/15/15, however since some individual cats only have a very small number of images, we make a requirement that at least 1 image will be in the val and test sets. This is stored in the folder `outputs/fcm_datasets/test1` and has the following structure:

```
outputs/fcm_datasets/test1/
├── back-leg/
│   ├── train/
│   │   ├── cat1/
│   │   ├── ...
│   │   └── cat10/
│   ├── val/
│   └── test/
├── ...
└── tail/
```

✋ We then sanitise the test set, as this will be the test set used for all the tests. For every folder, we check if the images correspond to that body part. (We found no mistakes in ours.)

### Test 2

We duplicate `test1` into `test2` and ✋ sanitise the train and val sets. We do this by going through every prediction made in each image of the 60% test set and checking whether the annotation is correct; the images in `outputs/yolo_25-15-60/predict_with_manual` help with this. We found 39 body parts incorrectly annotated by the YOLOv12 model. However, only 19 of these were in the train or val sets. The others were probably cut when we had to balance the dataset in preparation for the FCM. We also found that in some images, some body parts were annotated twice.

Incorrect labels are moved to their correct body part folder if the body parts were mixed up, but if a crop isn't a valid body part at all, it is deleted. We then have to balance the datasets again (the notebook does this). When rebalancing, we were even able to add back 1 or 2 images for some body parts and individuals from the pool of crops that were previously removed.

### Test 3a

We keep the sanitised test set and use the manual crops from Step 7 (all of the 60% test set) as the train and val sets. To avoid potential data leakage issues, for every crop in the test set that has a corresponding manual crop (same image and body part), we remove the manual crop. Reason being is that while they are different annotations of the same image and body part, we just wanted to rule out any possible data leakage issues. Then we balance the manual crops and split them into train & val (roughly 80/20).

### Test 3b

Test 3a has more than double the training and validation images of Test 2, so on its own it can't tell us whether manual annotations do better or whether there are simply more of them. For Test 3b, we duplicate `test3a` into `test3b` and randomly delete train & val images until each cat has the same number of images as in Test 2.

### Test 4

We combine the train & val sets of Test 3a (manual) and Test 2 (sanitised automatic), and keep the same test set. We used Test 2 rather than Test 1 because the FCM did slightly better on the sanitised data.

## Step 9: Training & Testing the FCM

The FCM uses a ResNet50 (pretrained on ImageNet) to extract features from each body part, concatenates the four sets of features (body, front leg, back leg, tail) and classifies the cat with a softmax layer.

* Notebook: `05_fcm_train_test`

For every test, we train the FCM on batch_size = 32, 16, 8, 4, 2 & 1 and epochs 10, 20 & 30. For each batch size and epoch, we train and test the model 5 times and take the average of the 5 test accuracies and test losses. The results are saved to `outputs/fcm_results/results.csv`.

---

## Step 10: Improving YOLOv12 (Optional)

The models in Steps 2 and 6 were trained with default settings and only 10–20 epochs, so they may not show YOLOv12's full potential. To see if tuning helps, we:

* increased the input image size from 640 to 896 pixels,
* trained the larger variants (`m`, `l` and `x`) for 150 epochs with batch sizes of 8 and 16, and
* tested them at confidence thresholds of 0.15, 0.25, 0.35 and 0.40.

This takes hours per model, so use a big GPU.

* Notebook: `06_yolo_parameter_tuning`
* Output: `outputs/yolo_tuning/scores.csv`

## Notes

* Results will differ a little from run to run, as model training is random. This is why each FCM setting is trained 5 times and averaged.
* Splitting and balancing use a fixed seed (123), so you get the same datasets every time. Our original balancing was not seeded.
* `00_make_yolo_splits` and the helpers for Tests 2–4 in `04_prepare_fcm_datasets` were written for this repository so every step can be run. Some of these steps were originally done by hand.
* The notebooks were last run end to end (on dummy data) with Ultralytics 8.4 and TensorFlow 2.21.
